# Daylight master design comparison

Compared the current app with [Master Design v1.1](DAYLIGHT_MASTER_DESIGN_V1_1.txt), recovered from the v3 archive, and the [hand-drawn concepts](../UIConceptReference.pdf). The written v1.1 takes precedence where an earlier concept differs.

The core manual loop is in place: fixed routines, separate deadlines and task sessions, manual scheduling, inline outcomes, user approval of project milestones, and saved daily reviews with a rules-based fallback. The planner has both 12-month layouts, and a scheduled task stays available under **All active** for additional sessions.

| Area                                       | What is still missing or partial                                                                                                                                                                                                                                                                                                                |
| ------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Adaptive daily review (§§7–8, example F)   | The review shows the same optional focus, blocker, and accomplishment fields before generation. Rules can flag missing facts, and AI can suggest questions in the finished report, but the app does not first pick the few material questions for that day and collect their answers before producing the assessment.                           |
| Milestone replanning (§5)                  | AI can propose new milestones and tasks for the current milestone. When an approved milestone slips, Daylight can explain pacing risk, but it has no dedicated flow to propose a revised date, compare it with the current date, and accept or reject the revision.                                                                             |
| Deadline-first planning (§§2, 4)           | The Deadlines page lets you add linked tasks by hand. Approved project milestones appear in Projects and the planner, but not in the Deadlines list. AI task breakdown is limited to approved project milestones; standalone deadlines cannot use it. Milestone task drafts contain titles and notes, without proposed sub-deadlines.           |
| Progress reporting (§11)                   | The daily report has one structured pacing status. Project health is shown elsewhere, but the daily report has no separate set of pacing flags for individual projects. The seven-day view counts outcomes and shows current project health; it does not summarize upcoming work or identify repeated blockers.                                 |
| Project visual and overall report (sketch) | Project cards show a linear milestone path and detail cards name dependencies. The branching dependency map and separate overall progress report from the sketch are absent. These are sketch differences, rather than firm requirements in the written v1.1.                                                                                   |
| Live integrations (§15)                    | Google sync and event deletion have fixture coverage; the real Google account flow and authenticated Supabase save still need a signed-in round trip. Gemini recommendations, drafts, and reports need a configured key and live validation. AI priorities are requested with a button; local suggestions are available when the planner opens. |

The first two product changes to tackle are adaptive review questions and a milestone revision flow. Both close a gap in the daily planning cycle without adding another setup screen. Background sync, automatic weekly delivery, and broader calendar conflict policies are open decisions. The separate Future Self reflection, handwriting recognition, and advanced analytics are outside the written v1.1 core.

- **Friday progress report.** On Friday, show the saved weekly write-up in a popup when Daylight opens and keep it in Progress. Opening Daylight can display the report. AI generation requires an explicit action.
- **AI-created tasks.** Most work tasks should come from the AI to-do workflow using deadlines, upcoming busy calendar events, short reports from previous days, and user-provided project updates. Keep manual task entry for errands.
